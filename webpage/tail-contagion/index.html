Tail-Contagion

Keep Victim's packets on time while both senders share a datapath core. Change Adversary's packet size and extra processing, then compare scheduling policies.

Packet limit
Every packet costs one token, regardless of size or extra processing.
Byte limit
A 1,024 B packet costs sixteen times as many tokens as a 64 B packet. Extra processing adds no bytes.
Time budget
A batch finishes before the core charges each sender for its actual CPU time. Extra scans and stamps consume that sender's budget. New credits repay debt before further budgeted service. Spare capacity remains available when no funded sender has waiting work.
Dedicated
Victim and Adversary each reserve a datapath core. An idle private core cannot help the other sender.

The batch slots show which packets are being processed. The outlined slot is the active packet. Read, copy, check, and stamp actions share the same processing area.

Playback starts at 0.2 µs per real second. Pause or use Step to inspect one action at a time. Speed changes only playback; it does not change simulated CPU costs, traffic, or budgets. Space pauses; R resets. Changing settings restarts the simulation with repeatable arrivals.

The counter, settings, packet timers, and CPU-time bills all use the same simulated microsecond clock. Packet handlers take fractions of a microsecond; batches contain up to four packets. Each packet travels the input belt for at least 0.65 µs. Its deadline is 4 µs from arrival, including time on the conveyors, in the queue, and in the core. A full timer turns amber; the packet briefly shakes and keeps an exclamation mark. Victim's missed count includes overdue packets still waiting. Delivered totals change only when a packet reaches the output bin. Utilization is cumulative busy time divided by reserved core time. These are teaching timings, not measurements from the paper.
